# CLAUDE.md

Senario Looper / MultiFX, 24HP Eurorack, Daisy Seed2 DFM. See README.md and SenarioHW/docs/design-notes.md.

- **The KiCad project is generated**: `SenarioHW/Kicad/scripts/design.py` is the source (parts, nets, floorplan); `build.sh` writes the schematic and the PCB. It refuses to overwrite an existing `Senario.kicad_pcb` without `FORCE=1`, because that destroys hand placement. Change the design in `design.py`, not in the `.kicad_sch` files.
- After a rebuild run `scripts/check_netlist.py` (schematic vs PCB nets; needs KiCad's Python and `kicad-cli sch export netlist --format kicadxml`), ERC and DRC. The last good state (2026-11-23, version-beta, front placed by hand step by step with the generator: `design.PLACED`; ERC 0, netlist 0 mismatches; DRC = unrouted + silkscreen + 3 courtyard overlaps left on purpose to look at (trimmers VR1 / VR2 against the PTL sliders 0.28 mm body gap, USB-C against the OLED and CV in 3 jack: courtyard only). The USB-C is the Hroparts D-14D (no locating holes: the old D-15C waiver is gone); the faceplate is a grey-aluminium look with black legends at the 10.0 mm plane, the OLED module screws to the faceplate (its 4 holes are in the plate, not on the board), the microSD is the vertical Yamaichi on the front (the SMD TF-01A on the back does not fit: 17.3 mm wide). Parked beside the board, not placed yet: mounting holes H1, H2, H5, H6. `design.py` features: `grp()` draws one channel / button on its own schematic row, `BLOCK_TITLES` names the blocks, `OLED_MODEL` switches the 0.96 / 1.3 in OLED (schematic, footprint, faceplate window), `CVO_RF` / `CVO_RG` set the CV out gain, `gen_faceplate.py` reads each footprint's hidden `Faceplate_Opening` property. The front floorplan is a starting point for a hand pass: after it, improve the generator from the hand-placed board.
- Symbol pin numbers must equal the footprint pad numbers, otherwise "Update PCB from Schematic" breaks the nets (that is why `Senario.kicad_sym` has `SW_Tact_LED_6pin` and `Jack_TRS`).
- `KicadLibs` is a submodule (private). A change there is two commits: in the submodule on a branch, then the pointer here. Never commit a pointer to a commit that is not pushed to KicadLibs' `main`.
- Nothing has been built or run on hardware: never claim a feature works.
